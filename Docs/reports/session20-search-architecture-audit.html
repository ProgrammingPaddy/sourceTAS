Where the compute went

The old solver's "billions of options per minute" were arithmetic candidates — tiny equations, not trajectories. The current production path put full exact trajectory optimization inside the innermost loop, then repeated it across acceptance regions and refinement profiles. Every step down this ladder is a different unit; the collapse is the architecture, not the simulator.

RefSolve is not deleted. It was built to answer "can the machinery recover an arbitrary reachable boundary condition, cold?" — a certification instrument. The error was promoting it into the ordinary mechanism behind every field query. The audit below shows both its genuine strength and the cost of that promotion.

The audit: one real problem, both arms

The instrument (forwardfield) builds one real Entrance problem deterministically — the f0→f1 transfer, from the yaw-15 launch root, exit selected by the composite window+cone score (72 admissible ticks, 601 u/s) — and runs the v0 forward sweep and the production RefSolve ladder on exactly the same physics.

Audit run 1 caught the priors red-handed. The fixture's fast/flat/high exit prior selected a south-diving state whose vertical strike window closes in ~3 ticks. The un-windowed sweep burned 48.7M exact ticks marching a dead domain; RefSolve burned its full 12,000-eval ladder on the same corpse. Priors are not reachability — the cancelled terms must run before any simulation. With the window rule, the same dead query resolves in ~3 ticks of arithmetic.

The scaling criterion — the architectural pass/fail

The forward representation passes: refining the field 16× multiplies covered cells ~17× while exact simulation work stays flat — one sweep, re-binned. The production inverse path fails the same criterion: its strikes are fixed per solve, so finer coverage demands new per-region solves — which is precisely the 84–85% duplication measured at global scale in sessions 18–19.

How sessions 18–19 led here

Session 18 — the march works

First real-map runs: launch aims, service order, horizons, and exit diversity each measured and fixed. The explorer autonomously chains f0→f1→f2 with every edge replaying bitwise; f3 blocked by slow arrivals. Entrance refinement measured at 98–99.5% of all wall-clock.

Session 19 — the smoking gun

The resource-preservation service lane lifted the f2 capability tail (606 u/s @ z 157 vs 510 @ 125) but couldn't buy f3 in an hour. The K-duplication instrument found 84–85% of all entrance evals re-solving ~5,400–6,000 distinct physical problems 4.2× over — policy-invariant. Duplication this structural pointed past batching to the formulation itself.

What happens next

1. The state equivalence/partition rule. Make the forward sweep's per-cell efficiency competitive with RefSolve on easy targets while keeping its one-sweep-many-cells scaling. The measured leaks: 4.8M strikes → 330 cells of information; 10.2M states lost at an arbitrary cap. Adaptive cells with exact representatives + certified optimistic envelopes + honest unresolved status.

2. Rebuild Entrance production on the forward field. RefSolve becomes the oracle (its 251 exclusive cells and 27 quality wins are the falsification feed), polisher, and witness constructor. Field values remain actual replayed trajectories — the old field's optimistic-composite failure stays dead.

3. Then G0R, with identical search semantics, and the wall-time ledger: unique physical problems, unique schedules, exact replays, total MoveTicks, states, edges.

Targets: real maps (30+ ramps, 60+ s) under 10 minutes, ~30 for exhaustive; basictest trending to seconds-to-sub-minute. The simulator's measured 1.4M ticks/s single-thread — with arithmetic-first pruning, honest compression, and untouched parallel headroom — is what makes those numbers reachable without trading away a single bit of exactness.
